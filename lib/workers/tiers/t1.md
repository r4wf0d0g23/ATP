# Worker Tier 1 — Scheduled Scanner

## Identity
- **Competency:** Bulk scan, schema conformance, conflict prevention
- **Trigger:** Cron (high frequency — default daily)
- **Model class:** `fast` (lowest cost, high throughput)
- **Session type:** Isolated (fresh context per run)
- **Authorization:** Read all, write reports, open PRs, update var metadata on clean pass

## Responsibility

T1 is the always-on baseline scanner. It runs on a schedule regardless of changes, providing continuous drift detection across the full protocol and variable library.

## Execution Sequence

```
1. INITIALIZE
   Load an initial snapshot of open PRs for situational awareness.
   NOTE: This snapshot ages during execution. It is NOT used for conflict checks.
   The authoritative conflict check happens per-PR immediately before each PR is created (step 4).

2. SCAN ALL PROTOCOLS
   For each file in protocols/ and templates/protocols/:
   a. Validate frontmatter against protocol.schema.json
   b. Check required fields: id, name, version, status, classification,
      semantic_summary, preload_size_class, triggers, requires, guardrails, escalation
   c. Check semantic_summary length ≥ 50 chars and contains ≥ 2 sentences
   d. Check preload_size_class is set and reasonable for declared requires
   e. Check triggers list has ≥ 1 entry
   f. Check no private content in public/template files (IPs, real credentials,
      real hostnames, deployment-specific commands)
   g. Check review_authority is a generic role, not a personal identifier

3. SCAN ALL VARS (instance deployment)
   For each file in atp-instance/vars/:
   a. Validate frontmatter against variable.schema.json
   b. Check required fields present
   c. Check last_verified is not older than 30 days for always-verify vars
   d. Check verify_cmd is present for always-verify and session-cache vars
   e. Check validator field is set

4. GENERATE OUTPUTS
   Before creating each PR:
     a. Re-fetch current open PRs (do not use the step-1 snapshot — it may be stale)
     b. Check the freshly fetched list for content overlap with this finding
     c. If conflict found → comment on the existing PR instead of opening a new one
     d. If no conflict → proceed to open PR
   Then for all findings:
   a. Open PRs for actionable findings (schema violations, missing fields,
      private content leakage, stale var metadata)
   b. Write report to atp-instance/reports/YYYY-MM-DD-t1-scan-<slug>.json
   c. Update last_verified + value_hash in var files where verify_cmd passed

5. ANNOUNCE
   Send summary to ops-console channel:
   "T1 scan complete: <N> files scanned, <M> findings, <K> PRs opened"
```

## Cron Configuration (template)

```bash
openclaw cron add \
  --name "atp-t1-scanner" \
  --cron "0 2 * * *" \
  --tz "UTC" \
  --session isolated \
  --model fast \
  --message "Execute ATP T1 worker scan per atp/lib/workers/tiers/t1.md. Scan all protocols and instance vars, check open PRs for conflicts, open PRs for findings, write report to atp-instance/reports/." \
  --announce \
  --channel <ops-channel> \
  --to <ops-channel-id>
```

## What T1 Does NOT Do
- Run `verify_cmd` (that's T3's deep validation role)
- Review or approve PRs
- Cleanse reports
- Make judgment calls on ambiguous findings — if uncertain, log as info, don't PR
